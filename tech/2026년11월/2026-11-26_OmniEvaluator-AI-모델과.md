### OmniEvaluator: AI 모델과 에이전트를 위한 통합 평가 프레임워크
원문: https://d2.naver.com/helloworld/4331341

- NAVER Engineering Day 10th에서 발표된 세션을 공개한 글로, NAVER Cloud의 이호동·박상희·류도훈이 AI 모델과 에이전트를 위한 통합 평가 프레임워크 OmniEvaluator를 소개합니다.
- 추론 엔진 4종(HF Transformers·vLLM·SGLang·상용 API)과 평가 프레임워크 4종(lm-eval-harness·lmms-eval·VLMEvalKit·built-in)을 하나의 중간 스키마로 연결해 텍스트·이미지·비디오·오디오 1,000개 이상의 벤치마크를 단일 인터페이스로 실행합니다.
- 모든 실행은 설정·예측·점수를 담은 아티팩트로 남아 그대로 재현할 수 있으며, CPU에서 동작하는 내장 Verifier가 프롬프트와 프레임워크 차이에 흔들리지 않는 채점 신호를 제공합니다.
- 2026년에 추가된 Agent Harness를 통해 기존 벤치마크에 옵션 두 개만 붙이면 툴 호출 궤적까지 채점하는 Agent 평가로 전환되며, 대시보드에서 요청·진행·결과·샘플을 한곳에서 확인할 수 있습니다.
- EMNLP 2026 System Demonstrations 논문(arXiv 2609.01315)과 공개 저장소(https://github.com/naver-ai/omni-evaluator) 링크가 함께 제공됩니다.

### 디자인 시스템이 있는데도 화면은 왜 제각각일까?
원문: https://toss.tech/article/loan_review

- 토스뱅크의 대출 심사 플랫폼은 버튼, 테이블, 필드 등 기초 컴포넌트를 갖춘 디자인 시스템이 있었음에도 대출 상품마다 화면 구성과 버튼 위치가 제각각이었다.
- 심사 확정을 위한 버튼 위치가 주택담보대출과 전세자금대출에서 서로 달라 운영 담당자가 담당 상품을 옮길 때마다 화면 사용법을 다시 익히고 교육해야 하는 부담이 발생했다.
- 디자이너는 원인을 파악하기 위해 상품별 화면을 단계별로 나란히 비교해 업무상 필요한 차이와 제작 시점이 달라 발생한 차이를 구분했다.
- UX 리서처와 함께 실제 운영 담당자를 인터뷰하고 관찰한 결과, 담당자들이 단계 순서대로만 일하지 않고 앞 단계로 돌아가거나 여러 화면을 띄워 정보를 교차 검증한다는 점을 확인해 단계와 무관하게 정보를 조회하거나 새 창으로 띄우는 장치가 필요함을 파악했다.
- 전담 디자이너 없이 각 팀 요청에 따라 빠르게 확장되며 화면 단위 배치 기준이 없었던 것이 원인이라고 판단해, 컴포넌트를 새로 늘리는 대신 반복되는 화면과 흐름을 화면 단위 패턴으로 정의하기로 했다.

- 바이트댄스 화산엔진의 클라우드 네이티브 벡터 데이터베이스 VikingDB는 동일 저장소 내에서 벡터 검색과 키워드 검색을 모두 지원하며 수십 개 내외부 검색 시나리오에서 운영되고 있다.

- 병음 보충 토크나이저를 활성화하면 쓰기 시 한자를 성조 없는 전체 병음과 다음자 복수 후보 발음으로 색인하므로 사용자가 한자 대신 병음 알파벳을 입력해도 해당 문서를 찾을 수 있다.

### 백엔드 구축 없이 프론트엔드 페이지에서 클라우드 데이터 연동: Pages Data SDK 정식 출시
원문: https://mp.weixin.qq.com/s?__biz=MzI1MzYzMjE0MQ==&mid=2247524676&idx=1&sn=d3c8dba365471f3ed41af535bebbead5

- 화산엔진 IGA Pages의 Pages Data SDK는 별도의 백엔드 서버나 데이터베이스를 구축하지 않고도 웹 페이지 앱이 Pages 서버 측 인터페이스를 통해 클라우드 데이터를 생성·조회·수정·삭제할 수 있도록 지원하며 앱 코드 자체는 데이터 자격 증명을 보유하지 않는다.
- Data SDK를 적용하면 여러 기기에서 동일한 데이터를 이어서 수정하는 '개인 워크벤치'와 교사가 올린 문제 이미지를 모든 가정이 공유하되 아이의 필기 기록은 각 기기 로컬에만 남기는 '공유 문제집' 같은 시나리오를 구현할 수 있다.
- TRAE 플러그인 마켓에서 IGA Pages Skill을 설치한 뒤, Node.js 22 이상이 필요한 Pages 콘솔의 Personal Workbench 템플릿으로 프로젝트를 시작해 Data SDK 동작을 확인하고 커스터마이징할 수 있다.

- 이미 브라우저 로컬에 데이터를 저장하는 기존 프로젝트도 TRAE에 Data SDK 참고 문서를 제공해 기존 화면과 인터랙션은 유지한 채 데이터 읽기·쓰기만 Pages 서버 측 API 호출로 전환할 수 있다.

### 한 문장으로 AI가 3D 세계를 만든다: 샤오홍슈, 3DCodeFactory 오픈소스 공개
원문: https://mp.weixin.qq.com/s?__biz=Mzg4OTc2MzczNg==&mid=2247497241&idx=1&sn=a61dd75ab206dca94419055ef76dd1e4

- 샤오홍슈는 기존 3D 에셋에 의존하지 않고 일반 텍스트만으로 복잡한 3D 모델링 과제와 다차원 검수 기준을 자동 합성한 뒤 샌드박스 실기 평가로 멀티턴 궤적을 선별하는 3DCodeFactory 프레임워크를 공개했다.
- 이 프레임워크로 구축해 오픈소스로 공개한 데이터셋 3DCodeFactory-Data는 5,045개의 3D 과제와 멀티턴 상호작용 궤적을 포함하며, 궤적당 평균 100만 토큰 이상, 단일 장면 코드량 중앙값 4,270줄, 총 5.52B 토큰 규모이다.
- 데이터 합성 파이프라인은 10개 상위 영역과 56개 세부 범주의 3D 분류 체계로 텍스트 분포를 정렬한 후, 합성 참고 이미지를 시각적 앵커로 삼아 3D 메시 및 Three.js 상호작용 과제와 시각·규격·기능 평가 기준을 동시에 생성한다.
- 코드 에이전트가 격리된 샌드박스에서 코드 작성·렌더링·수정을 반복해 생성한 결과물은 다각도 시각 검증과 소스·상호작용 테스트 기반 규격·기능 검증의 5개 지표 기준을 모두 충족한 궤적만 학습셋에 포함되며, 이중맹검 인간 평가에서 결함 차단 정확률 87.2%, 재현율 91.1%, 인간-기계 일치율 77.3%를 기록했다.
- 3DCodeFactory-Data로 1에폭 미세조정한 Qwen3.8-27B 모델은 BlenderWorld, P3D-Bench, 3DCodeBench 벤치마크 종합 성능에서 동일 계열 2.4T 플래그십 모델인 Qwen3.8-Max와 기존 오픈소스 3D 코드 데이터셋 기반 모델을 앞섰다.
